### 1.1 原始需求复述（用户原话）

> "帮我开发一个计算器 app，用于安卓系统使用，功能齐全，操作便捷，可以按照 org.solovyev.android.calculator 这个包名原型 Calculator++ 进行仿照开发。计算器的应用名字叫 Calculator-planover。"
> 注：该选型已于 2026-09-11 由用户变更——applicationId 改为 com.planover.calculatorplanover，以避免与侧载的原版 Calculator++ 同包名冲突。

### 1.2 已拍板选型（不可推翻）

1. **技术栈**：Rust 语言计算引擎 + Flutter 工具链 UI
2. **交付形态**：完整源码工程 + GitHub Actions 自动构建 APK
3. **功能广度**：完整科学计算器全套 + 增强 + 单位换算功能

### 1.3 架构补充决策（架构师裁决，已同步进本 PRD）

1. **FFI 方案 = C ABI + C 字符串 JSON，零代码生成。** 理由：本机无 Dart/Flutter SDK，代码生成类方案（如 `flutter_rust_bridge`）一旦出问题无法在本地复现修复，故选择无 codegen 的确定性方案。
2. **Rust 侧拆双 crate**：`calculator_core`（rlib，全部逻辑 + 全部测试）与 `calculator_ffi`（cdylib，仅胶水），全部 API 语义收进 `dispatch(method, json, &mut Engine) -> String`。理由：把 FFI 的 JSON 契约也纳入 `cargo test` 本地覆盖，扩大本地可验证面。

## 2. 产品定义

### 2.1 产品目标

- **G1｜还原 Calculator++ 的核心手感**：以"可编辑表达式行 + 实时预览"取代逐字符累加式输入，让用户像编辑一行文本一样编辑算式，光标可任意移动、任意位置删改、括号自动配对。
- **G2｜一套引擎覆盖全部计算场景**：基础四则、科学函数、进制转换、单位换算均由同一套 Rust 引擎实现，保证结果一致、精度可控、行为可测试。
- **G3｜工程可持续、可验证**：Rust 计算逻辑 100% 可用 `cargo test` 在本地真实验证；Flutter UI 由 GitHub Actions 保障可分析、可测试、可构建，形成"核心真验证 + UI 自动化验证"的分层质量闭环。

### 2.2 目标用户与使用场景

| 用户画像 | 场景 | 关键诉求 |
|---|---|---|
| 理工科学生 | 课堂上做高数/大物/电路作业，算式长、改得多 | 表达式可编辑可回看、三角函数角度制、科学计数法 |
| 工程师 / 现场技术人员 | 现场量测后快速换算单位（inch↔mm、psi↔bar、MB↔GiB） | 单位换算快、常量随手可取、结果可复制 |
| 程序员 | 位运算与进制转换（0xFF、0b1010、DEC/HEX 互转） | 进制切换直观、按位运算 |
| 日常用户 | 算账、算折扣、算百分比 | 上手即用、历史记录能找回上一次结果 |

### 2.3 核心用户故事

- **US-1**｜作为理工科学生，我想像编辑文本一样在输入行里移动光标修改算式中间的一项，以便不用整条删掉重打。
- **US-2**｜作为学生，我想在输入过程中就实时看到当前算式的结果预览，以便立刻判断括号有没有写错。
- **US-3**｜作为工程师，我想把 12.7 inch 一键换算成 mm，以便不用记忆换算系数。
- **US-4**｜作为程序员，我想在 DEC / HEX / OCT / BIN 之间快速切换同一个数值，以便做位运算调试。
- **US-5**｜作为日常用户，我想从历史列表里点一条旧算式回来继续改，以便复用上次的计算。
- **US-6**｜作为重度用户，我想把结果精度设为"保留 4 位小数"并让它一直生效，以便输出格式稳定。
- **US-7**｜作为夜间使用者，我想让计算器跟随系统切换深色主题，以便不刺眼。

## 3. 需求池

> **验证方式标记说明**
> - `[R]` = Rust `cargo test` 单元测试 / 表驱动测试 / JSON 契约测试，**本地可真实验证**（当前机器装了 Rust 即可跑，无需 Java / Android / Flutter / Dart SDK）。v1.1 起，对 `api::dispatch` 喂 JSON 断言输出的**FFI 契约测试也归入此类**
> - `[F]` = Flutter `flutter test` / `flutter analyze`，**CI 中验证**
> - `[C]` = CI 构建验证（`flutter build apk` 三 ABI 产出成功 + 产物完整性校验）
> - `[M]` = 人工真机验收

### 3.1 P0 —— 必须有（Must have）

#### A. 表达式输入与求值

| ID | 需求 | 验收标准 | 验证 |
|---|---|---|---|
| P0-01 | **可编辑表达式输入行**（单行，超长自动横向滚动）：光标可通过点击或方向键移动到任意位置，支持在任意位置插入/删除字符。**编辑逻辑归 Rust**（R1 裁决）：Flutter 不实现任何插入/删除/括号配对逻辑，每次按键/退格/删除均构造 `EditRequest` 调 `calc_apply_edit`，用返回的 `EditResult{text,cursor,changed}` 覆盖输入框状态；**唯一例外**是纯光标移动（点击定位、方向键、Home/End），无计算语义，由 Flutter 本地处理 | 以下 **①–⑤** 为**可直接断言**的场景（①③ 为主理人指定的两条核心场景，②④⑤ 为本版补充），全部在 Rust 侧以 `EditRequest → EditResult` 形式单测：<br>**① 中间插入**：`text="1+2*(3-4"`, `cursor=1`, 插入 `'0'` → 返回 `text="10+2*(3-4)"`, `cursor=2`（注意：补上缺失右括号后光标仍为 2）；<br>**② 中间退格**：`text="1234"`, `cursor=2`, 退格 → 返回 `text="134"`, `cursor=1`（删的是**光标前**一个字符，不是末尾字符）；<br>**③ 括号配对落点**：`text=""`, 插入 `'('` → 返回 `text="()"`, `cursor=1`（光标落在配对括号中间）；随后在中间输入 `1+2` 再输入 `)` → `text="(1+2)"`, `cursor=5`（跳过已有右括号，不重复插入）；<br>**④ 字符索引约束**：`cursor` 为 **字符索引（char index）而非字节索引**——对 `text="2π+√3"`, `cursor=4` 插入 `'x'` → `text="2π+√x3"`, `cursor=5`（若误用字节索引，`π`/`√` 各占 3 字节会导致错位与 panic）；<br>**⑤ `changed=false` 语义**：本次编辑未产生任何文本变化时返回 `changed=false`，Flutter 可据此跳过重绘 | `[R]`（**主**：`calc_apply_edit` 表驱动单测，覆盖上述 5 类场景 × 多字节字符用例）+ `[F]`（辅：纯光标移动与 `EditResult` 覆盖输入框的绑定）+ `[M]`（辅：真机点选手感） |
| P0-02 | **括号自动配对**：输入 `(` 自动补 `)` 并把光标置于两者之间；当右括号已存在且光标紧邻时再输入 `)` 为"跳过"而非重复插入 | 1) 输入 `(` 得到 `()` 且光标在中间；2) 在 `()` 中间输入 `1+2` 再输入 `)`，结果为 `(1+2)` 而非 `(1+2))`；3) 删除左括号时若配对右括号为空则成对删除；4) `matching_paren` 也走 **Rust**（R1 裁决），Flutter 不本地实现配对查找；5) 全部返回值遵循 P0-01 第 ④ 条的**字符索引**约定（非字节索引） | `[R]`（`calc_apply_edit` 与 `matching_paren` 的纯函数单测，**本地可验证**）+ `[F]`（键盘按键 → `EditRequest` 的连线） |
| P0-03 | **实时预览 / 即时求值**：每次表达式变化（防抖 ≤ 120ms）调用引擎求值并显示在预览行；表达式不完整或语法错误时预览行显示错误提示而非崩溃 | 1) 输入 `1+2*` 时预览行显示"表达式不完整"提示；2) 补 `3` 后预览行显示 `7`；3) 输入 `1/0` 显示"除数不能为零"；4) 连续快速输入 20 次不出现 UI 卡顿或异常 | `[R]` 引擎 `evaluate` 对 30 组不完整表达式返回 `Err(IncompleteExpression)`；`[F]` 防抖定时器测试；`[M]` |
| P0-04 | **四则运算 + 括号 + 优先级 + 一元正负号 + 百分号** | 已裁决基线（Q2/Q4）：`-3^2` = **-9**（一元负号优先级**低于**幂，若需 `9` 必须写 `(-3)^2`）；百分号 `a%` 等价 `a/100`，故 `200*10%` = **20**。断言集：`1+2*3`=7；`(1+2)*3`=9；`-3^2`=-9；`(-3)^2`=9；`50%`=0.5；`200*10%`=20；`10-(-3)`=13；设置页"计算"分组用一行文字明示 `-3^2 = -9` 规则 | `[R]` 表驱动单测，覆盖 ≥ 40 条表达式与其期望值，其中 `-3^2`/`(-3)^2`/`200*10%` 三条为必测基线 |
| P0-05 | **等号提交**：按 `=` 提交当前表达式，结果写入历史、更新 `ans`、并把结果作为新的可编辑表达式起点 | 1) 提交后 `ans` 等于该结果；2) 紧接着输入 `ans*2` 得到 2 倍结果；3) 历史列表新增一条含"表达式 / 结果 / 时间戳"的记录；4) 已裁决（Q9）：**`ans` 独立于历史存储，执行"清空历史"不重置 `ans`** | `[R]` 会话状态机单测（含清空历史后 `ans` 仍可读的断言）；`[F]` 交互测试 |
| P0-06 | **运算符与函数优先级正确**：`^` 右结合、函数优先级高于乘除、隐式乘法（`2(3+4)`、`2π`） | 已裁决（Q3）：**支持隐式乘法**。断言：`2^3^2`=512；`sin30` (DEG)=0.5；`2(3+4)`=14；`2π`≈6.283185307 | `[R]` 单测 |
| P0-07 | **错误定位与提示**：解析失败时返回错误类型 + 字符偏移区间，UI 可在该位置高亮 | `1+*2` 返回 `Err{ kind: UnexpectedToken, span: 2..3 }`，Flutter 侧可据此给该区间加红色下划线 | `[R]` 断言 span 精确；`[F]` 断言高亮渲染 |

## 5. 数据流简述

```
┌───────────────────────── Flutter (Dart) ─────────────────────────┐
│                                                                  │
│  ExpressionField ──(文本/光标变化, 防抖120ms)──┐                   │
│                                               ▼                   │
│  SettingsProvider ──(angleMode, numberFormat,  │                  │
│                      precision, fractionMode) ─┤                  │
│                                               ▼                   │
│                                   CalculatorController           │
│                                          │                        │
│                          ffi_bindings.dart (dart:ffi 手写绑定)     │
│                          DynamicLibrary.open('libcalculator_ffi.so')│
└──────────────────────────────────────────┼────────────────────────┘
                                           │  C ABI：*const c_char → *mut c_char
                                           │  （载荷 = UTF-8 JSON 字符串）
                                           ▼
┌──────────────────── engine/ffi ── calculator_ffi (cdylib) ───────┐
│   calc_evaluate_preview / calc_evaluate_commit / calc_convert …   │
│   calc_apply_edit / calc_list_* / calc_set_* / calc_version       │
│   calc_string_free                                                │
│        │  只做：CStr→String → dispatch → CString；panic 全兜住     │
└────────┼─────────────────────────────────────────────────────────┘
         ▼  dispatch(method, json, &mut Engine) -> String   ← 纯字符串函数
┌──────────────────── engine/core ── calculator_core (rlib) ───────┐
│                                                                  │
│   api::dispatch ──▶ 按 method 分发到各 API                        │
│        │                                                         │
│        ├─ Lexer  ──▶ Token 流（含 span 位置信息）                  │
│        ├─ Parser ──▶ AST（Pratt 解析，^ 右结合，函数最高优先级）     │
│        ├─ Resolver ─▶ 绑定常量表 / 变量表 / 函数表                 │
│        ├─ Evaluator ▶ Num { Rational(i64/i64) | Float(f64) }      │
│        └─ Formatter ▶ EvalResult {                               │
│                          value, display, fraction,                │
│                          base{bin,oct,dec,hex}, assignments }     │
│                                                                  │
│   convert(v, from, to) ──▶ UnitTable 查维度 → 仿射/比例换算        │
│   list_constants() / list_units(cat) / set_variable(k, v)         │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘
                                           │
                                           ▼  Envelope JSON 字符串
┌───────────────────────── Flutter (Dart) ─────────────────────────┐
│   jsonDecode → Envelope{ok,data,error} → 领域模型                  │
│   预览行渲染 display / 错误高亮 span                               │
│   进制行渲染 base                                                  │
│   按 "=" → calc_evaluate_commit → 入历史 + 更新 ans                 │
│   历史/设置 → 本地持久化（sqflite / SharedPreferences）             │
└──────────────────────────────────────────────────────────────────┘
```

**关键约定**

1. **单一数据源**：所有数值计算、格式化、进制转换、单位换算、常量/变量求值**只在 Rust 侧完成**，Flutter 不做任何数值运算（避免双实现不一致）。
2. **错误不可抛异常跨 FFI**：Rust 侧统一返回 `Envelope{ok,data,error}`，`error` 含 `code` + `kind` + `message` + 可选 `span`；FFI 层把 panic 也兜成 JSON 错误码，**绝不 unwind 跨 FFI 边界**。
3. **纯函数优先**：Lexer/Parser/Formatter/UnitTable/BaseConverter 均为纯函数；`api::dispatch` 本身也是纯字符串函数，可在 Rust 侧直接单测，不依赖 Android 运行时、不依赖 linker。
4. **双 crate 隔离（架构师决策）**：`calculator_core` 只产 rlib（承载全部逻辑与全部测试），`calculator_ffi` 只产 cdylib（仅 CString/serde 胶水）。**意义：FFI 的 JSON 契约本身也能被 `cargo test` 覆盖**，把"跨语言边界"这一最大的验证盲区拉进本地可验证范围。同时 workspace 默认只构建 rlib，本机无 linker 也能跑测试。
5. **历史持久化位置**：历史数据**存储**在 Flutter 侧（已裁决 Q7：`sqflite`，上限 500 条），Rust 侧只负责**计算与格式化**，避免 Rust 侧引入文件 IO 依赖；因此接口清单中**不含** `get_history`，改为 `calc_reset_session` 管理 Rust 侧会话态（`ans` 与变量）。
6. **零代码生成**：Dart 侧手写 `dart:ffi` 绑定，`extern "C"` 函数签名与 JSON DTO 是**唯一契约**，双方都不得引入 codegen 工具链（理由见 §1.3）。
7. **编辑逻辑归 Rust（R1 裁决）**：Flutter 侧**不实现**任何插入 / 删除 / 括号配对逻辑。每次按键、退格、删除都构造 `EditRequest` 调 `calc_apply_edit`，用返回的 `EditResult{text,cursor,changed}` 直接覆盖输入框状态；**唯一例外**是纯光标移动（点击定位、方向键、Home/End），因其无计算语义，由 Flutter 本地处理；`matching_paren` 同样走 Rust。
8. **光标索引单位（强制）**：`cursor` 一律为**字符索引（char index），不是字节索引**。表达式含 `π`、`×`、`√`、`°` 等多字节字符，误用字节索引会导致中文/符号光标错位甚至 panic。跨 FFI 传输时按 UTF-8 字节传字符串，但**语义层与 Dart 侧一律按 char index 解释**。

## 7. 已裁决问题（Decision Log）

> v1.1 更新：v1.0 提出的 12 个待确认问题**已由主理人全部裁决完毕**，本节由「待确认」转为决策留档。裁决结果已回填至 §3 需求池对应条目的验收标准，工程师请以本节 + 对应验收标准为准。

| # | 问题 | **裁决结果（生效）** | 回填位置 |
|---|---|---|---|
| Q1 | 数值精度方案 | **`Num` 枚举 = 有理数 `Rational(i64/i64)` ∪ `f64`**。分数/有理数路径走 Rational（精确），超越函数（sin/ln/exp/…）退化为 f64。**禁止**引入 GMP 等需外部 C 库的依赖（约束 C7）。有理数溢出 i64 时自动降级 f64 且不 panic | P0-18、P0-31、§6.1 C7 |
| Q2 | `-3^2` 的解释 | **= -9**（一元负号优先级**低于**幂）。需要 `9` 时必须写 `(-3)^2`。设置页"计算"分组用一行文字明示 | P0-04 |
| Q3 | 隐式乘法是否支持 | **支持** `2(3+4)`、`2π`。标识符后紧跟 `(` 时：若为已知函数则解析为函数调用，否则按隐式乘法处理 | P0-06 |
| Q4 | 百分号语义 | **`a%` 等价 `a/100`**，故 `200*10%` = **20**、单独 `50%` = 0.5 | P0-04 |
| Q5 | 阶乘定义域 | **仅非负整数**。`2.5!`、`(-1)!` 均返回 `DomainError`。v1 不引入 Gamma 函数，**已登记为 P2-10**（非整数阶乘，R2 批准） | P0-11、P2-10 |
| Q6 | 位运算位宽与负数表示 | **默认 64 位宽、二进制补码**；位宽 8/16/32/64 可在设置中切换。64 位宽下 `~0` = -1，`-1` 的 HEX 为 `FFFFFFFFFFFFFFFF` | P0-14、P1-06、§4.3 设置页"默认位宽" |
| Q7 | 历史存储与上限 | **Flutter 侧 `sqflite`，上限 500 条**，超出自动裁剪最旧记录 | P1-01、§5 关键约定 5 |
| Q8 | 温度换算 | **走仿射变换路径**（非纯比例），与比例型单位分开处理。低于绝对零度（< 0 K / < -273.15 °C）返回 `DomainError` | P0-15 |
| Q9 | `ans` 与历史的关系 | **`ans` 独立于历史**：不计入历史条目，执行"清空历史"**不重置** `ans` | P0-05、P0-20 |
| Q10 | 桌面小部件 | **v1 不做**，保留 P2-01 候选。需原生 Android Kotlin/Java 代码，与"Flutter 为主"架构冲突，留待后续单独立项 | P2-01（标题已标 ⛔ v1 不做）、§6.3 非目标 |
| Q11 | CI 工具链版本锁定 | **锁定**：Flutter 使用当前稳定版（在 workflow 中显式指定版本号），Rust 通过仓库内 **`rust-toolchain.toml`** 锁定 | P0-29 |
| Q12 | APK 签名 | **CI 默认产出 debug / 未签名 APK**；release 签名密钥经 **GitHub Secrets** 注入，为可选路径 | P0-29 |

**裁决带来的净变化**：Q1、Q2、Q4 三条直接改变了 P0-04 / P0-18 / P0-31 的数值基线（v1.0 中这三条的验收标准带"按约定求值""待确认"字样，v1.1 已全部替换为确定数值）。Q5 的"Gamma 放 P2"承诺已于 v1.2 登记为 P2-10，消除悬空。

### 7.1 本版本已知验证缺口（R3）
