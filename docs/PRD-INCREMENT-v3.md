## 2. 问题陈述与根因归属

> **本节是本次整改的核心。** 每条问题必须归入一种**缺口类型**，因为缺口类型决定整改方式：
> - **规范缺口（Spec Gap）**：既有 PRD 里**根本没有写**这条要求 → 必须先补规范（本 PRD §4/§5），否则工程师照旧文档无从实现、QA 无从断言。
> - **实现缺口（Impl Gap）**：规范已写、但代码**没做或做错** → 直接派工修复，规范无需改。
> - **验证缺口（Verify Gap）**：规范已写、代码看起来做了、但**从未被真正验收** → 必须补验证手段并闭环。

### 2.1 问题清单（8 项）

| # | 用户抱怨（原话） | 代码实况（已 grep 实证） | 既有 PRD 要求 | **缺口类型** |
|---|---|---|---|---|
| **P-1** | 点按没有震动反馈 | `AndroidManifest.xml` 声明了 `VIBRATE` 权限，但**全项目 grep `HapticFeedback` 零结果**；设置页无触感开关 | **P1-04**（触感反馈可开关）、**P1-11**（持久化清单含触感开关） | **实现缺口**（权限声明了却完全未实现） |
| **P-2** | 界面错章杂乱 | `app/lib/src/theme/app_theme.dart` 的 `buildTheme()` **只设 `useMaterial3` / `colorScheme` / `brightness`**——无 `textTheme`、无任何组件主题（按钮/卡片/列表/抽屉/键盘全无） | P0-23 主界面布局（仅线框图，**无组件主题规范**） | **规范缺口 + 实现缺口**（既有 PRD 未定义组件主题，代码也无） |
| **P-3** | 字体大小不协调 | `app/lib/src/theme/tokens.dart` 只有 **6 个写死的绝对 dp**（`fontSizeExpr=28`/`Preview=22`/`Result=40`/`Key=22`/`Label=14`/`Base=16`），**无字阶、无相对比例、无响应式缩放** | **无明确规范**（基线 PRD 仅在 §4.1 散落提到"28sp/20sp"） | **规范缺口**（无 type scale 定义） |
| **P-4** | 要适配所有显示屏幕 | `app/lib/src/ui/home_screen.dart` 是裸 `Column`（DisplayPanel→ExpressionField→FunctionTabs→Expanded(Keypad)），**无 `LayoutBuilder`、无断点、无横屏分支、无平板宽度约束、无 `OrientationBuilder`** | **P1-10** 横屏分栏（`[M]`）；**总体无"响应式/屏幕适配"章节** | **规范缺口（主）+ 实现缺口** |
| **P-5** | 应用图标太丑 | `app/android/app/src/main/res/drawable/ic_launcher_foreground.xml` 为 **431 字节**手写矢量（白色粗 "E" 形 path）；`res/` 下只有 `drawable/`、`mipmap-anydpi-v26/`、`values/`，**无任何 `mipmap-*dpi` PNG 集** | 仅有 P0-26（应用名）；N5 强制"不得复制原版图标/资源" | **规范缺口**（从未定义图标设计规范） |
| **P-6** | 其他语言压根没适配 | `app/assets/i18n/` 下**只有 3 个文件**（`en.json`/`zh-CN.json`/`zh-TW.json`），`en.json` 仅 **120 个 key**；而 `locale_registry.dart` 注册了 **216 档**语言 | **LG-05/LG-06：P0+P1 = 20 门为硬性要求**（增量 v2 §7.2） | **实现缺口**（规范已定 20 门，实际只交付 3 门） |
| **P-7** | 切换语言界面卡死、也不会变为其他语言 | 两个**独立**缺陷：<br>**(a) 语言不变**：全项目 **16 处**以 `Provider.of<LocaleController>(context, listen: false).l10n` 读取文案（`settings_screen` 12 处 + `constants_panel`/`history_sheet`/`keypad`/`memory_sheet` 各 1 处）→ 这些 Widget **不订阅** LocaleController，语言切换后其文案不刷新（注：`_LanguageRow` 自身用了 `listen: true`，故"部分文案变、部分不变"）。<br>**(b) 卡死**：`app.dart` 把 `LocaleRegistry.supported`（**216 条**）整体塞进 `MaterialApp.supportedLocales`；设置页语言选择器是 `DropdownButton`，**一次性构建 216 个 `DropdownMenuItem`**（`settings_screen.dart:210`） | **LG-04**（完成度% UI）**完全未实现**；无性能规范 | **(a) 实现缺口**（订阅方式错）；**(b) 规范缺口 + 实现缺口**（无选择器性能规范，实现用全量 Dropdown）；**LG-04 为规范缺口/未实现** |
| **P-8** | （其他语言适配的一部分）RTL 语言排版错误 | `AppLocalizations.isRtl` 已定义（`app_localizations.dart:110`）、`LocaleRegistry.isRtl` 已定义，单测也覆盖，但**全项目无任何消费方**（无 `Directionality` 使用）→ 31 档 `rtl: true` 语言会按 **LTR 排版** | 增量 v2 §7.2 中约 30 档标 `rtl: true`，但**无 RTL 接入要求** | **规范缺口 + 实现缺口** |

### 2.2 关键结论（写入问题陈述，供决策）

> **这些缺陷早被预判为验证缺口，但从未闭环。** 基线 PRD 已把 **P0-23（主界面布局）** 与 **P1-10（横屏布局）** 显式标注为 `[M] 真机验收`，并在 §7.1 自陈"本项目本地无模拟器环境，提测时作为遗留项显式列出"。
>
> 换言之：**这些视觉 / 布局 / 交互缺陷在文档层面就被打上了"未验证"标签，然后一路漏到用户手里**。用户此番真机反馈，实质上就是**那次一直没有执行的验收**。
>
> **本次整改的机械化要求**：任何视觉 / 布局 / 交互类需求，**必须同时给出可自动断言的判据（`[D]`）**，不能只留 `[M]`。`[M]` 只做"观感最终确认"，不再承担"唯一验收手段"。

### 2.3 缺口类型汇总

| 缺口类型 | 涉及问题 | 整改动作 |
|---|---|---|
| **规范缺口** | P-2（组件主题）、P-3（字阶）、P-4（响应式）、P-5（图标）、P-7b（选择器性能）、P-8（RTL） | 先补本 PRD **§4 屏幕适配矩阵** 与 **§5 设计体系规格**，再派工 |
| **实现缺口** | P-1（触感）、P-2（同）、P-4（同）、P-6（语言包）、P-7a（订阅）、P-7b（选择器）、P-8（Directionality） | 按 §3 需求池派工 |
| **验证缺口** | P-2/P-4/P-5 的历史教训（P0-23、P1-10 从未真机验收） | §8 每条新增 `[D]` 判据 + 提测清单强制闭环 |

## 3. 需求池（P0 / P1 / P2）

> **编号规则**：本次新增需求统一用 **`UX-xx`**（延续基线 `P0-xx` / `P1-xx` / 增量 v2 `UI-xx`/`TH-xx`/`LC-xx`/`RF-xx`/`LG-xx`/`CP-xx` 的 ID 风格）。

## 4. 屏幕适配矩阵（**新增章节**，PRD 此前缺失）

> 本章回答用户"要适配所有显示屏幕"。**目标：任意目标设备档位，主界面不溢出、触摸区达标、可读。**

### 4.1 设计基准与逻辑单位

| 项 | 取值 |
|---|---|
| 逻辑单位 | **dp（Flutter 逻辑像素）**，断点一律用**可用宽度 dp**（`LayoutBuilder` 的 `constraints.maxWidth`），**不用物理像素** |
| 基准栅格 | 4dp（§5.3） |
| 最小触摸区 | **44×44dp**（沿用 P1-10 / P1-14；**在任意档位均成立**） |
| 参照设计档 | 常规 6.4" 竖屏（可用宽 ≈ 411dp） |

### 4.2 目标设备档位矩阵

| 档位 | 代表设备 | 可用宽度（竖屏 dp） | 布局策略 | **验收标准** |
|---|---|---|---|---|
| **S｜小屏** | 4.7"–5.5"（iPhone SE 类 / 老安卓） | **< 360**（如 320–359） | 键盘 5×5 保持；两侧内边距降到 `padSm(8)`；结果显示区字号取字阶**下限一档**；功能页签可横向滚动 | 无溢出；按键命中 ≥ 44dp；结果区超长不截断（缩字号或横向滚动） |
| **M｜常规** | 6.1"–6.7"（主流） | **360–599** | 基准布局（三区纵向堆叠 + 键盘 5×5） | 无溢出；键盘区与显示区比例可视协调（真机观感） |
| **L｜大屏／折叠外屏** | 6.7"+ / 折叠外屏 | **410–599** | 同 M，但左右内边距升到 `padLg(16)`；结果区最大字阶 | 内容不被横向拉伸到难读；无溢出 |
| **XL｜平板／折叠内屏** | 7"–12" | **≥ 600** | **宽度约束**：主内容居中含 `maxContentWidth`（建议 600dp），两侧留白；键盘按钮**不无限拉宽**（高度相应增加，保持接近正方形） | 主内容不被拉伸至整屏宽；按键长宽比 ≤ 2:1；无溢出 |
| **P｜横屏** | 上述任意设备的横向 | 可用**高度** < 可用宽度 | **分栏**：显示区一栏、键盘一栏（见 §4.4） | 无纵向溢出；键盘按键 ≥ 44dp；显示区与键盘均完整可见 |

### 4.3 断点定义（宽度）

| 断点名 | 宽度区间（dp） | 语义 |
|---|---|---|
| `compactSmall` | `< 360` | 小屏竖屏 |
| `compact` | `360 ≤ w < 600` | 常规竖屏 |
| `medium` | `600 ≤ w < 840` | 平板竖屏 / 大屏横屏 |
| `expanded` | `≥ 840` | 大平板 / 折叠内屏（可双窗格，UX-12） |

> 断点**同时考虑方向**：横屏判定用 `orientation == landscape`（等价于 `mediaQuery.width > height`）。横屏时**优先走向 §4.4 分栏**，宽度断点用于决定分栏后的栏宽与是否进一步双窗格。

### 4.4 横屏策略

| 场景 | 策略 |
|---|---|
| 横屏且高度 **< 480dp**（小屏/常规机横屏） | **强制分栏**：左栏显示区（结果 + 表达式）、右栏键盘。理由：纵向堆叠在低高度下必然溢出。 |
| 横屏且高度 **≥ 480dp**（大屏/平板横屏） | 分栏（左显示右键盘）；宽度 ≥ 840dp 时可再开第二窗格（历史常驻） |
| 分栏比例 | 显示区 : 键盘 ≈ `4 : 6`（键盘优先保证按键 44dp 下限） |
| 是否**允许**用户关闭分栏 | 见 §9 **Q1**（推荐：强制分栏，不提供关闭开关，避免引入第二套布局维护成本） |

### 4.5 字号缩放边界与降级（对应 UX-07）

| 参数 | 取值 | 说明 |
|---|---|---|
| 系统字号下限 | **0.8** | 低于此值 clamp 到 0.8（防过小不可读） |
| 系统字号上限 | **1.5** | 高于此值 clamp 到 1.5（防布局彻底崩溃） |
| 正常区间 | `[0.8, 1.5]` | 字阶整体等比缩放，布局不降级 |
| **紧凑降级触发** | 1.5 档仍溢出时 | ① 减少装饰性留白（`padXl → padLg`）；② 非核心标签可省略 / 缩写；③ 结果区允许**换行两行**；④ 键盘按钮文字可降一档字阶（**命中区仍 ≥ 44dp，不得缩小**） |
| 硬约束 | — | 任意缩放档位下，**按键命中区 ≥ 44dp** 且**核心功能（输入/求值/复制）可用** |

## 5. 设计体系规格要求（**新增章节**）

> 用户原话："你去读读美学要求，读读设计规范再做事吧。" 本章把"美学要求"写成**可验收条款**——工程师可直接实现，QA 可直接断言。

### 5.1 设计体系总则

| # | 总则 | 可验收表述 |
|---|---|---|
| D-1 | **单一来源** | 所有字号 / 间距 / 圆角 / 色彩 **只能**来自 token（`theme/tokens.dart`），UI 层**禁止**裸值（`[D]` grep 断言） |
| D-2 | **主题只换色、不换形** | **所有主题共用同一套字阶、间距、圆角、组件形状**；主题之间**仅语义色彩不同**（`[D]` 逐主题断言字阶一致） |
| D-3 | **组件主题全覆盖** | `buildTheme()` 必须为 §5.5 列出的**每类组件**提供主题，不得有"只有色、没有形"的组件 |
| D-4 | **对比度达标** | 满足 §5.4 的 WCAG 阈值（`[D]` 逐主题断言） |
| D-5 | **RTL 无关性** | 设计体系不得使用 `left/right` 语义，一律用 `start/end`（`[D]` grep 断言，服务于 UX-03） |

### 5.2 字阶（Type Scale）—— 6 级，所有主题共用

> 基准比例 ≈ **1.25（Major Third）**；以 16dp 为 body 基准向上/下推导。字号为**基准 dp**，实际渲染再乘系统缩放（§4.5）。

| 级别 | Token 名 | 基准字号 | 字重 | 行高 | 用途 |
|---|---|---|---|---|---|
| **Display** | `fontSizeResult` | **40** | W400 | 1.15 | 结果显示区（大字号结果） |
| **Headline** | `fontSizeExpr` | **28** | W400 | 1.2 | 表达式输入行 |
| **Title** | `fontSizePreview` | **22** | W400 | 1.25 | 实时预览行 / 面板标题 |
| **Body** | `fontSizeBase` | **16** | W400 | 1.4 | 设置项正文 / 列表主文本 |
| **Label** | `fontSizeLabel` | **14** | W500 | 1.4 | 设置项副标题 / 次要文本 |
| **Caption** | `fontSizeCaption` | **12** | W400 | 1.4 | 时间戳 / 辅助说明（新增，补足层级） |
| **Key** | `fontSizeKey` | **22** | W400 | 1.0 | 键盘按键文字 |

**验收断言**：
1. `[D]` 字阶为**有限枚举**（上述 7 个 token），UI 层出现其他字号即失败；
2. `[D]` 相邻级比例 ∈ [1.15, 1.4]（保持层级可辨）；
3. `[D]` **所有主题**的上述 7 个 token 数值**完全一致**（D-2）；
4. `[D]` 数字与运算符键使用**等宽数字**（`fontFeatures: tabularFigures`），防跳字。

### 5.3 间距栅格（Spacing Grid）

| Token | 值（dp） | 用途 |
|---|---|---|
| `padXs` | 4 | 图标与文字间隙 |
| `padSm` | 8 | 紧凑内边距（小屏降级） |
| `padMd` | 12 | 组件内边距 |
| `padLg` | 16 | 页面主内边距（基准） |
| `padXl` | 24 | 区块间距 |
| `pad2xl` | 32 | 大留白（新增，平板/大屏） |

**验收断言**：`[D]` 所有间距为 **4 的整数倍**；`[D]` UI 层无裸间距值。

### 5.4 色彩语义与对比度（WCAG）

| 语义 token（继承增量 v2 §4.3 的 15 个） | 使用规则（唯一用途） |
|---|---|
| `colorAccent` | **仅**用于运算符键、选中态、主操作；**不得**用作装饰性大面积底色 |
| `colorKeyOperator` | 运算符键强调色 |
| `colorKeyFunction` | 函数键背景 |
| `colorError` | **仅**用于错误态（错误文案 / 错误区间高亮）；不得他用 |
| `colorSuccess` | **仅**用于成功/已保存态 |
| `colorTextPrimary` / `colorTextSecondary` | 主文本 / 次要文本 |
| `colorDivider` | 分隔线 / 边框 |

**对比度阈值（逐主题断言，`[D]`）**：

| 内容类型 | 阈值 | 依据 |
|---|---|---|
| 正文文本（≤ 18.66dp） | **≥ 4.5:1** | WCAG AA |
| 大文本（≥ 24dp，或 ≥ 18.66dp 粗体） | **≥ 3:1** | WCAG AA |
| 非文本 UI 元素（图标/边框/按键边界） | **≥ 3:1** | WCAG AA |
| **高对比主题**（High Contrast） | **≥ 7:1** | WCAG AAA（承接增量 v2 TH-05） |
| 按下态（`colorKeyPressed` vs 常态） | **可区分**（ΔL ≥ 0.05 或明度差 ≥ 8%） | 可感知反馈（`[D]` 断言） |

> **禁止**：任何主题出现"前景=背景"或对比度 < 3:1 的文本（含未校订语言的置灰项——置灰须仍 ≥ 4.5:1，用 `colorTextSecondary` 而非降透明度到不可读）。

### 5.5 组件主题（Component Themes）—— `buildTheme()` 必填清单

> 现状 `buildTheme()` **只有 3 个字段**（`useMaterial3`/`colorScheme`/`brightness`），这是"界面错章杂乱"的直接原因。以下组件主题**必须全部补齐**：

| # | 组件主题 | 必含内容 |
|---|---|---|
| 1 | `textTheme` | §5.2 的 7 级字阶（**当前完全缺失**） |
| 2 | `elevatedButtonTheme` / `filledButtonTheme` / `outlinedButtonTheme` / `textButtonTheme` | 形状（§5.6 圆角）、内边距、文字样式、最小高度 ≥ 44dp |
| 3 | `iconButtonTheme` | 尺寸 ≥ 44dp、图标色、点击态 |
| 4 | `cardTheme` | 圆角 `radiusMd`、`colorSurface`、边距 |
| 5 | `listTileTheme` | 标题/副标题字阶、内边距、选中态色 |
| 6 | `dialogTheme` | 圆角 `radiusLg`、标题字阶、按钮样式 |
| 7 | `bottomSheetTheme` | 圆角、`colorSurface`、拖拽把手 |
| 8 | `appBarTheme` | 标题字阶、图标色、高度（48dp） |
| 9 | `dividerTheme` | 粗细 1dp、`colorDivider` |
| 10 | `inputDecorationTheme` | 边框圆角、填充色、错误态色 |
| 11 | **键盘按键主题**（项目自定义 `KeyButton`） | 圆角、按压态（`colorKeyPressed`）、三类键（数字/运算/函数）配色、水波反馈 |
| 12 | `snackBarTheme` | 圆角、`colorSurface`、文字色 |

**验收断言**：`[D]` 上述 12 类组件主题在 `buildTheme()` 返回的 `ThemeData` 中**均非 null**（当前 1–12 全为 null）。

### 5.6 形状（Shape / Radius）

| Token | 值（dp） | 用途 |
|---|---|---|
| `radiusSm` | 8 | 小控件（标签/徽标） |
| `radiusMd` | 12 | 卡片、按键 |
| `radiusLg` | 16 | 对话框、底部抽屉 |
| `radiusPill` | 999 | 胶囊段控件（DEG/RAD/GRAD） |

**验收断言**：`[D]` 圆角取自上述 token；`[D]` 按键圆角统一（不得同屏出现两种按键圆角）。

### 5.7 应用图标规范（对应 UX-08）

| 项 | 规格 |
|---|---|
| 形态 | **自适应图标**（`<adaptive-icon>`：`background` + `foreground` + `monochrome`） |
| 画布 | 108×108dp；**安全区 72×72dp**（前景主体必须完整落在安全区内，安全区外为系统裁切余量） |
| 分层 | 背景层 + 前景层分离；前景层透明，主体居中 |
| 多密度 | 提供 `mipmap-mdpi/hdpi/xhdpi/xxhdpi/xxxhdpi`，或矢量 + `[M]` 确认 5 档密度不模糊 |
| 主题图标 | `monochrome` 单色层（Android 13+ 主题图标） |
| 视觉 | **极简几何**：推荐主体为等宽字体的运算符符号（如 `∑` / `=` / `π` 择一）或计算器抽象几何；**48dp 显示下最小笔画 ≥ 2dp** 可辨识 |
| **净室（N5）** | **原创设计**，与 Calculator++ 原版图标**无视觉复制**；不复制其任何资源 |

## 9. 待确认问题（需用户 / 主理人拍板）

> 每项均给出**推荐选项 + 理由**，不留空。

| # | 问题 | **推荐选项** | 理由 |
|---|---|---|---|
| **Q1** | **横屏是否强制分栏？** 是否允许用户关闭分栏回到纵向堆叠？ | **强制分栏，不提供关闭开关**（§4.4） | 低高度（< 480dp）下纵向堆叠**必然溢出**，不是偏好问题；提供开关会引入**第二套布局的长期维护成本**，且用户一旦关掉又会报"错乱"。若确需弹性，可仅在大屏横屏（高度 ≥ 480dp）提供"分栏/堆叠"切换。 |
| **Q2** | **应用图标风格倾向？** | **极简几何 + 运算符符号**（推荐 `∑` 或 `π` 单符号；备选：抽象计算器轮廓 / 等号方阵） | ① 计算器图标品类同质化严重，**符号化**辨识度最高、缩放不失真；② 与"科学计算器"定位一致；③ 单符号最易满足 **72dp 安全区**与"48dp 下最小笔画 ≥ 2dp"的可辨识要求；④ 与原版（Calculator++ 图标）**无视觉相似**，天然满足 N5。**备选问题**：是否要加应用首字母 `C`？推荐**不加**（多字符在 48dp 下易糊）。 |
| **Q3** | **语言选择器交互方式？**（UX-02 定形） | **可搜索的底部弹层（`showModalBottomSheet` + 搜索框 + 懒加载 `ListView`）**，母语名 + 英文名并列展示，未校订项带完成度标记 | ① 216 项靠 `DropdownButton` 一次构建必然卡（已实证）；② 搜索是 216 项的**必要可用性**（用户不可能滚动找 `zh-CN`）；③ 底部弹层在手机上是**原生惯用**的列表选择模式，且天然支持 RTL 镜像（配合 UX-03）；④ 懒加载 + 搜索双保险，性能断言（P95 ≤ 100ms）可达成。备选：全屏页面选择器（适合平板），可作为 XL 断点下的形态。 |
| **Q4** | **系统字号缩放上下界？** | **clamp [0.8, 1.5]** + 超限紧凑降级（§4.5） | Material 建议上限约 1.3–1.5；低于 0.8 不可读、高于 1.5 布局必崩。配合降级策略兼顾无障碍（WCAG 1.4.4 缩放）与可用性。 |
| **Q5** | **触感反馈强度是否分档？** | **本期单档 + 开关**（不分强度档） | 分档（轻/中/重）需精细调参与真机反复校准，收益低、风险高；先保证"有反馈 + 可关"，强度档列入后续。 |
| **Q6** | **字阶基准比例？** | **1.25（Major Third）** | 6 级在手机有限高度内层级清晰、不浪费垂直空间；1.333（Perfect Fourth）在小屏（< 360dp）下 Display/Headline 跨度过大易溢出。 |
| **Q7** | **20 门语言交付批次？**（人力） | **分两批**：第 1 批 P0 三门（en/zh-CN/zh-TW，已基本就绪）+ 高价值 7 门（ja/ko/de/fr/es/pt-BR/ru）；第 2 批余下 10 门。**每批均须过 §3.2 UX-10 的覆盖率/占位符断言** | 一次性 20 门质量不可控；分批可在第 1 批先跑通"覆盖率 ≥ 99% + 占位符一致"的流水线，第 2 批复用。需确认是否有外部翻译资源（承接增量 v2 Q6）。 |
| **Q8** | **20 门语言是否需要母语者审校？** | **不要求母语者级**，采用"**机器初翻 + 人工抽检（≥ 3 门）**"，并在 UX-09 完成度中如实标注 | 母语者审校 20 门成本极高且不在本轮预算；"覆盖率 + 占位符 + 抽检"已能保证**可用性**，且完成度 UI 本身让用户知情。 |

### 9.1 最需用户拍板的 3 个问题（摘要）

1. **Q1 横屏是否强制分栏** —— 直接决定布局架构与工作量（影响 UX-05、UX-12）。
2. **Q2 应用图标风格倾向** —— 主观美学，无法由团队替用户定；图标一旦定稿返工成本高。
3. **Q3 语言选择器交互方式** —— 直接决定 UX-02 的实现形态与性能断言（可搜索弹层 vs 全屏页面）。
