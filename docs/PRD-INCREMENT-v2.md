#### ⚠️ 裁决 D1：`=` 键与 calculate-on-fly（需主理人确认，见 §9 Q1）

**背景冲突**：基线 PRD 的 5×5 键盘**含 `=` 键**；原版主键盘**没有 `=` 键**，`=` 只存在于悬浮/简单键盘。用户本次明确要求"严格仿照…交互逻辑也保持一致"。

**我的产品裁决（建议）**：

1. **主键盘去掉 `=` 键**，第 5 行第 5 位改为 `🕘` 历史（严格仿照）。
2. **calculate-on-fly 默认开启**（与原版一致）：边输入边计算，结果显示区实时更新，无需按 `=`。
3. **`=` 键迁移到 Simple 模式键盘**（对应原版的悬浮/简单键盘），Engineer 模式下不出现。
4. **显式提交入口保留三处**（补偿移除 `=` 后的操作习惯）：
   - 物理键盘 `Enter`
   - 结果显示区**长按 → "保存到历史"**
   - Simple 模式的 `=` 键

|---|---|---|---|
| UI-10 | **主键盘无 `=` 键**（裁决 D1） | 遍历全键盘 label 集合，断言不含 `=` | `[D]` |

## 5. 语言与区域格式分离（I3）

### 5.1 核心建模

**语言（Language）** 负责 **界面文案**；**区域格式（Region Format）** 负责 **数字、货币、时间、日期的显示规则**。二者**完全独立，可任意组合**（对齐 Windows 明确允许的能力，修正原版"小数分隔符随界面语言变"的缺陷）。

| ID | 需求 | 验收标准 | 验证 |
|---|---|---|---|
| LC-01 | **新增独立设置项 `区域格式（Region Format）`**，与既有 `语言（Display Language）` 并列 | 设置页同时存在两个独立项，均可单独修改且互不影响 | `[D]` |
| LC-02 | **`语言` 选项**：`跟随系统` / 显式选择（从 216 档语言清单中选） | 选择 `en` 时全部 UI 文案为英文；选 `zh-CN` 时为简体中文；选 `ja` 时若无人事校订译文则回落英文并显式标注（见 LC-08） | `[D]` + `[M]` |

## 8. 架构影响（须架构师确认）

| # | 影响点 | 说明 | 建议 |

| A1 | **数字/货币格式化必须在 Rust 侧** | 基线约定"所有数值格式化只在 Rust 完成"。区域格式影响数字/货币显示 → 需把 `RegionFormatConfig` 作为参数经 `dispatch` 传入 Rust | 新增 `set_region_format` 方法，配置随 `EvaluateRequest` 传入 |
